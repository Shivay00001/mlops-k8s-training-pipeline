## 🚀 Overview

Welcome to the **Mlops K8S Training Pipeline** repository. This project is built to deliver a robust and scalable solution tailored to modern development standards.

At its core, this repository currently provides a **containerized FastAPI inference service** designed to be deployed as part of a Kubernetes-based MLOps workflow. It exposes an ML model-serving HTTP API (health checks + prediction endpoint) packaged in a Docker image, intended as the serving layer of a broader training/deployment pipeline.

## ✨ Features

- **High Performance:** Optimized for speed and efficiency.
- **Scalable Architecture:** Designed to grow with your needs (stateless service, horizontal-scaling friendly).
- **Clean Codebase:** Follows best practices and industry standards.
- **Secure by Default:** Engineered with security in mind (secrets excluded via `.gitignore`).
- **REST Inference API:** FastAPI-based `/predict` endpoint with a `/` health check returning the model version.
- **Container-Ready:** Ships with a `Dockerfile` for consistent, reproducible deployments on any laptop, server, or Kubernetes cluster.

## 🏗️ Architecture / How It Works

The serving layer is implemented in `main.py` using **FastAPI** and **NumPy**:

```
Client Request
      │
      ▼
┌─────────────────────────────────────┐
│  Uvicorn ASGI Server (port 8000)    │
│  ┌───────────────────────────────┐  │
│  │         FastAPI App           │  │
│  │  GET  /        → health check │  │
│  │       returns status +        │  │
│  │       model_version (v2.4.1)  │  │
│  │                               │  │
│  │  POST /predict → accepts JSON │  │
│  │       payload, generates a    │  │
│  │       128-dim feature vector, │  │
│  │       returns class_id +      │  │
│  │       confidence score        │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

**Request flow:**

1. **Health check** — `GET /` returns `{"status": "operational", "model_version": "v2.4.1"}`, suitable for Kubernetes liveness/readiness probes.
2. **Inference** — `POST /predict` accepts a JSON body, simulates inference by generating a 128-dimensional random vector, and returns the argmax as `class_id` and the max value as `confidence`.

> ⚠️ **Note:** The current `/predict` endpoint performs *simulated* inference (random vectors). It is a placeholder where a real trained model (e.g., a PyTorch/scikit-learn artifact, given the dependencies in `requirements.txt`) would be loaded and invoked.

**Intended pipeline role:** this service acts as the *serving* component of an MLOps pipeline — training artifacts would be produced elsewhere, versioned, mounted/baked into this image, and deployed to Kubernetes behind an ingress with horizontal pod autoscaling.

## 📦 Installation

Follow standard installation steps for `Python` to set up the project locally:

1. Clone the repository:
   ```bash
   git clone https://github.com/Shivay00001/mlops-k8s-training-pipeline.git
   ```
2. Navigate to the project directory:
   ```bash
   cd mlops-k8s-training-pipeline
   ```
3. Create a virtual environment and install dependencies:
   ```bash
   python -m venv .venv
   source .venv/bin/activate   # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```

## 💻 Usage

### Run locally (without Docker)

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

Then test the endpoints:

```bash
# Health check
curl http://localhost:8000/

# Prediction
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"features": [0.1, 0.2, 0.3]}'
```

Interactive API docs (auto-generated by FastAPI) are available at `http://localhost:8000/docs`.

## 🐳 Running with Docker

The repository includes a `Dockerfile` based on `python:3.9-slim`, so it runs identically on any laptop or server.

### Build and run with Docker

```bash
# Build the image
docker build -t mlops-k8s-training-pipeline .

# Run the container (maps container port 8000 → host port 8000)
docker run -d -p 8000:8000 --name mlops-serving mlops-k8s-training-pipeline
```

Verify it is running:

```bash
curl http://localhost:8000/
# → {"status":"operational","model_version":"v2.4.1"}
```

### Run with Docker Compose (optional)

A `docker-compose.yml` is not currently included in the repository, but the following minimal file works out of the box:

```yaml
services:
  mlops-serving:
    build: .
    ports:
      - "8000:8000"
    restart: unless-stopped
```

Then simply run:

```bash
docker-compose up --build
```

### Kubernetes deployment (target environment)

Since the service is stateless, it deploys cleanly to Kubernetes. Use the `/` endpoint for probes:

```yaml
livenessProbe:
  httpGet: { path: /, port: 8000 }
readinessProbe:
  httpGet: { path: /, port: 8000 }
```

## 🔍 Workability Assessment

In the interest of full transparency, here is an honest evaluation of the repository's current state:

**What works:**
- ✅ The FastAPI application runs correctly and both endpoints (`/` and `/predict`) function as written.
- ✅ The `Dockerfile` builds successfully and produces a working container.
- ✅ Secrets hygiene is good — `.gitignore` properly excludes credentials and environment files.
- ✅ The service is stateless and therefore genuinely suitable for Kubernetes horizontal scaling.

**What is incomplete / needs work:**
- ⚠️ **No actual model training pipeline exists yet.** Despite the repository name, there is no training code, data ingestion, experiment tracking, model registry integration, CI/CD, or Kubernetes manifests in the current codebase. The name describes the *intended* system, not the current contents.
- ⚠️ **Inference is simulated.** `/predict` returns random values rather than loading a real model artifact. Before production use, a trained model (PyTorch/sklearn) must be loaded at startup and used for inference.
- ⚠️ **Bloated dependencies.** `requirements.txt` includes heavy packages (`torch`, `scikit-learn`, `pandas`) that the current code never imports. This inflates the Docker image significantly and slows builds. Trim them or use them.
- ⚠️ **Missing operational essentials:** no tests, no input validation schema (Pydantic models), no logging configuration, no pinned dependency versions, and no `docker-compose.yml` or K8s manifests committed.
- ⚠️ **Dockerfile could be hardened:** no non-root user, no pinned base image digest, and `pip install` without `--no-cache-dir`.

**Verdict:** This repository is a **solid, working skeleton** for an ML serving service and a good starting point — but it is **not production-ready** as an "MLOps training pipeline." It requires the actual training pipeline, real model loading, tests, and deployment manifests before it can honestly claim that title.
